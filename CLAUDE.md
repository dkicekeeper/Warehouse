# Warehouse

Сервис владельца для ведения всех его проектов. Сейчас строится первая подсистема —
**диспетчерская**: закрытая страница и бот Telegram, которые показывают «Ждёт вас», общую очередь
сборок macOS и связь проект ↔ сессии Claude ↔ PR.

- Дорожная карта: [docs/roadmap.md](docs/roadmap.md)
- Спецификация: [docs/superpowers/specs/2026-11-25-dispatch-design.md](docs/superpowers/specs/2026-11-25-dispatch-design.md)
- План: [docs/superpowers/plans/2026-11-25-dispatch.md](docs/superpowers/plans/2026-11-25-dispatch.md)
- Next.js здесь новее, чем в обучающих данных: правила в [AGENTS.md](AGENTS.md), документация в
  `node_modules/next/dist/docs/`.

```bash
pnpm install
pnpm test        # vitest

```

## Правила

- Никаких секретов в репозитории (он публичный): только имена переменных в `.env.example`.
- Сборка и тесты только на `ubuntu-latest`; ни одного задания на macOS.
- Без входа владельца не отдаётся ничего. Открыты только `/login`, `/auth/callback` и приёмники
  (`/api/github/webhook`, `/api/report/*`, `/api/telegram/webhook`, `/api/cron/tick`), каждый со
  своей проверкой подписи или токена.
- К базе ходит только сервер ключом service role; RLS включён на всех таблицах без политик.
- Из сессий в базе хранится только разобранное состояние, строка состояния и не более 300
  символов хвоста сообщения.
- Вся логика — чистые функции в `lib/domain/`, покрытые тестами; сначала падающий тест, потом код.
- Тексты интерфейса и сообщений — на русском, идентификаторы в коде — на английском.
- Оценки времени в интерфейсе — со знаком «~»; неизвестное — «~?».
