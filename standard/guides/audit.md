# Аудит

Как это устроено: аудит — проход агента по всем репозиториям владельца с этими гайдлайнами в руках.
Автоматические проверки (lint.py, линт DesignKit, CI) запускаются как есть; правила с проверкой
«аудит» агент сверяет сам. Каждое расхождение становится задачей: в проекте, если проект
отступил от правила, или в Warehouse, если устарело само правило. Итог — сводка с цифрами и
ссылками, её видит владелец.

## Как проводить

1. Взять свежие `main` всех репозиториев: Warehouse, Tenra, Dalada, Platina, DesignKit, Baja.kz.
2. Запустить автоматические проверки: `python3 -I <Warehouse>/standard/lint.py --root <репозиторий>`
   везде; в приложениях `python3 <DesignKit>/scripts/designkit_lint.py all --source <папки Swift>`.
3. Пройти правила с проверкой «аудит» по их полю «Где»: для каждого — да, нет или неприменимо, с
   доказательством (файл, строка, workflow).
4. Записать находки (AUD-2, AUD-3) и сводку (AUD-4).

### AUD-1. Аудит проверяет каждое правило там, где оно действует

Правило: аудит проходит все правила гайдлайнов по их полю «Где» и запускает все автоматические
проверки; правило, которое не проверено, в сводке названо с причиной.

Почему: правило без проверки — пожелание (дизайн гайдлайнов, одобрен владельцем 2026-11-27).

Проверка: аудит

Где: Warehouse

Агенту: нет

### AUD-2. Расхождение проекта — задача в проекте

Правило: если проект не следует правилу, в его `docs/backlog/` появляется задача: `type: chore`,
что не так и где, ссылка на номер правила в «Заметках». Задачи уходят PR с одними документами,
по одному на репозиторий.

Почему: работа проекта видна в его бэклоге и на панели Warehouse; PR с документами не запускают
сборки macOS (`ci.md`, CI-2).

Проверка: аудит

Где: все

Агенту: нет

### AUD-3. Устаревшее правило — предложение, а не правка

Правило: если правило не подходит проекту, устарело или его стоит распространить на другие
проекты, агент заводит задачу `idea` в `docs/backlog/` Warehouse с предложением; само правило
меняют только после решения владельца.

Почему: правила записывают решения владельца (`README.md`).

Проверка: аудит

Где: Warehouse

Агенту: нет

### AUD-4. Сводка аудита

Правило: итог — файл `docs/archive/audit-<ГГГГ-ММ-ДД>.md` в Warehouse: сколько правил проверено,
что выполнено, что нет, ссылки на заведённые задачи и предложения; краткая сводка — в сообщении
сессии.

Почему: владелец видит итог одним документом; следующий аудит сравнивает с прошлым.

Проверка: аудит

Где: Warehouse

Агенту: нет

## Коротко для агента

- Нашёл, что проект отступил от правила гайдлайнов, — запиши задачу в `docs/backlog/` со ссылкой
  на номер правила; правило устарело — предложение задачей в Warehouse, правило не меняй
  (`standard/guides/audit.md`).
