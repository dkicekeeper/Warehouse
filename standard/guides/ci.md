# Сборки и CI

Как это устроено: код часто пишется в облачном контейнере на Linux, где приложения iOS не
собираются. Поэтому компилятор для них — CI на GitHub Actions: сессия пушит ветку и читает логи.
Раннеров macOS у аккаунта несколько на всех (Tenra, Dalada, Platina, DesignKit), и они дорогие,
поэтому workflow приложений собирают только то, что изменилось. Очередь сборок macOS видна на
панели Warehouse. Всё остальное (Warehouse, Baja.kz, тесты без UI) идёт на ubuntu.

### CI-1. CI — компилятор: запушил — прочитай логи

Правило: код, который нельзя собрать в контейнере (SwiftUI, приложение), проверяет CI; после пуша
сессия читает логи прогона и чинит ошибки, а не считает работу сделанной.

Почему: записано в `CLAUDE.md` Platina, Dalada и DesignKit («CI is the compiler»).

Проверка: аудит

Где: приложения, DesignKit

Агенту: да

### CI-2. Раннеры macOS берегут

Правило: workflow на macOS запускается только когда изменилось то, что он собирает (фильтры путей
или `ci_changes.py`), новый пуш в ту же ветку отменяет незаконченный прогон, а коммит, который уже
собран в ветке, не собирается второй раз в её PR или в `main`.

Почему: раннеры общие на четыре репозитория; лишняя сборка задерживает чужую (записано в
`CLAUDE.md` Dalada и Platina, `ci.yml` Tenra, `ci_changes.py` DesignKit).

Проверка: аудит

Где: приложения, DesignKit

Агенту: да

### CI-3. Warehouse собирается только на ubuntu

Правило: сборка и тесты Warehouse — только на `ubuntu-latest`, ни одного задания на macOS.

Почему: записано в `CLAUDE.md` Warehouse; сервис не занимает раннеры приложений.

Проверка: аудит

Где: Warehouse

Агенту: нет

### CI-4. Проверка стандарта в каждом репозитории

Правило: в репозитории проекта есть `.github/workflows/standard.yml` — копия
`standard/workflow.yml` Warehouse без правок. У Warehouse свой вариант: он проверяет собственную
ветку, а не `main`.

Почему: он проверяет `docs/` на каждом PR и раз в сутки обновляет блок стандарта в `CLAUDE.md`.

Проверка: аудит

Где: все

Агенту: нет

## Коротко для агента

- Код, который не собирается в контейнере, проверяет CI: запушил — прочитай логи прогона (CI-1).
- Раннеры macOS общие на все приложения: не запускай их зря, лишняя сборка задерживает чужую
  (CI-2).
