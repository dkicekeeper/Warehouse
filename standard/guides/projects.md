# Проекты

Как это устроено: у владельца шесть проектов, каждый — репозиторий в аккаунте GitHub
`dkicekeeper`. Три приложения iOS: Tenra (личные финансы, в App Store), Dalada (рыбалка и отдых в
Казахстане, в App Store Казахстана), Platina (трофеи PlayStation, бета). Общая для них библиотека
интерфейса DesignKit. Сайт-каталог Baja.kz. Сервис Warehouse — этот: он видит сессии Claude, PR и
сборки всех проектов, показывает, что ждёт владельца, и задаёт стандарт. Работу в проектах ведут
сессии Claude Code (`sessions.md`); владелец решает, мержит, проверяет на устройстве.

### PRJ-1. Проект — это репозиторий с паспортом

Правило: каждый проект — отдельный репозиторий `dkicekeeper/<Имя>` с паспортом `docs/project.md`:
что это, для кого, стадия, чем проект занят сейчас.

Почему: решение владельца [«Стандарт: полная унификация»](https://github.com/dkicekeeper/Warehouse/blob/main/docs/decisions/2026-11-26-standard-full-unification.md).

Проверка: lint.py `passport`

Где: все

Агенту: нет

### PRJ-2. Проект подключён к Warehouse

Правило: на репозиторий установлено приложение GitHub сервиса Warehouse (вебхуки PR и сборок,
чтение `docs/`), проект привязан к нему в настройках сервиса.

Почему: без этого проект не виден на панели: ни его сессии, ни PR, ни задачи (`docs/setup.md`
Warehouse).

Проверка: аудит

Где: все

Агенту: нет

### PRJ-3. Работа — в ветке, в main — через PR

Правило: сессия работает в ветке `claude/…` и приносит работу в `main` через PR с зелёным CI.
Прямо в `main` пишут только боты своих workflow: подъём версии DesignKit в приложениях, блок
стандарта в `CLAUDE.md`, релиз-бот DesignKit.

Почему: стандарт (DoD: «CI репозитория зелёный на ветке», закрытая задача переносится «тем же
PR»); код приложений пишется на Linux и компилируется только в CI (`ci.md`).

Проверка: аудит

Где: все

Агенту: да

### PRJ-4. Новый проект — по чеклисту

Правило: новый проект начинается с копии `standard/template/`, паспорта, первой задачи,
`.github/workflows/standard.yml` и хука отчёта сессии.

Почему: чеклист «Новый проект» стандарта; так проект с первого дня виден сервису и проходит
проверку.

Проверка: lint.py `tree` | аудит

Где: все

Агенту: нет

## Коротко для агента

- Работай в ветке `claude/…`; в `main` — только через PR с зелёным CI. Прямо в `main` пишут
  только боты своих workflow (PRJ-3).
