# Дизайн-системы

Как это устроено: у владельца две дизайн-системы.

**DesignKit** — пакет SwiftUI для всех трёх приложений (Tenra — эталон вида, Dalada, Platina).
Три модуля: токены (цвета, отступы, шрифты, анимации), поддержка (иконки, форматирование) и
компоненты, разложенные по тому, что они делают. Приложение Gallery показывает каждый компонент с
параметрами и состояниями (TestFlight). Каждый PR в DesignKit получает номер версии при мерже
(релиз-бот), CI DesignKit собирает против изменения все три приложения, поэтому поломка видна до
релиза. Приложения закрепляют точную версию; их workflow **DesignKit update** раз в сутки
поднимает её, собирает, гоняет тесты и коммитит в `main`. Правила: `docs/design-system.md`
DesignKit (полные), `docs/components.md` (по компоненту), `docs/agents.md` (выжимка — её workflow
вставляет в `CLAUDE.md` приложений между метками `designkit:agents`). Линт
`scripts/designkit_lint.py` ловит сырые значения и неправильные строки секций; CI приложений
запускает его той версии, на которой собрано приложение.

**Сайты** (Warehouse, Baja.kz) — на shadcn/ui поверх Tailwind: компоненты добавляет CLI shadcn,
цвета — токены темы, тёмная тема по системной настройке.

Тексты интерфейса — отдельная тема каждого проекта (языки, тон); общие правила — ниже.

## DesignKit

### DES-1. Интерфейс приложений — на DesignKit

Правило: весь интерфейс приложения собирается из DesignKit; компонента, которого нет, добавляют
PR в DesignKit с нейтральным именем, а в приложении остаётся тонкий переходник к его модели.

Почему: решение владельца (2026-10): DesignKit — единственный источник того, как всё выглядит,
даже если компонент нужен одному приложению (записано в `CLAUDE.md` DesignKit, Tenra, Dalada,
Platina).

Проверка: аудит

Где: приложения

Агенту: да

### DES-2. Только токены

Правило: цвета, шрифты, отступы, радиусы, анимации — только токены DesignKit; без смахиваний и
системного `Form`.

Почему: правило DesignKit для приложений (`docs/agents.md`).

Проверка: линт DesignKit `tokens` (CI приложений) | аудит

Где: приложения

Агенту: да

### DES-3. Версию DesignKit поднимает workflow

Правило: версию DesignKit в приложении меняет workflow **DesignKit update**, не человек; новый
компонент сначала выходит релизом DesignKit.

Почему: записано в `CLAUDE.md` Tenra, Dalada, Platina; workflow проверяет сборку и тесты перед
коммитом.

Проверка: аудит

Где: приложения

Агенту: да

### DES-4. Блок DesignKit в CLAUDE.md не правят руками

Правило: блок между метками `designkit:agents` в `CLAUDE.md` приложения меняют в `docs/agents.md`
DesignKit; workflow приложения перепишет его.

Почему: записано в самом блоке и в `CLAUDE.md` DesignKit.

Проверка: аудит

Где: приложения

Агенту: да

### DES-5. У компонента с данными есть скелетон

Правило: каждый компонент, который показывает данные, имеет скелетон `<Имя>Skeleton` той же
формы; пока данные грузятся, показывают его.

Почему: решение владельца (2026-10), записано в `CLAUDE.md` DesignKit.

Проверка: аудит

Где: DesignKit, приложения

Агенту: нет

### DES-6. Публичный API не ломают в минорной версии

Правило: публичное API DesignKit не удаляют и не переименовывают в минорном релизе: помечают
устаревшим с заменой и удаляют в следующей мажорной, когда им никто не пользуется.

Почему: записано в `CLAUDE.md` DesignKit («API Stability & Versioning»).

Проверка: аудит

Где: DesignKit

Агенту: нет

## Сайты

### DES-7. Сайты — на shadcn/ui и токенах темы

Правило: интерфейс сайтов — компоненты shadcn/ui; цвета только токенами темы (`bg-card`,
`text-muted-foreground`, `text-destructive` и свои токены), без `bg-gray-*` и подобных.

Почему: записано в `CLAUDE.md` Warehouse и Baja.kz.

Проверка: аудит

Где: Warehouse, Baja.kz

Агенту: да

## Тексты интерфейса

### DES-8. Каждая строка — в каталоге строк, на всех языках

Правило: строка интерфейса приложения — ключ в каталоге строк проекта с переводом на все его
языки; захардкоженного текста нет.

Почему: записано в `CLAUDE.md` Tenra (12 языков), Dalada (ru, kk, en), Platina (ru, en).

Проверка: аудит

Где: приложения

Агенту: да

### DES-9. Коротко и без длинных тире

Правило: тексты интерфейса и магазина — коротко и просто, без длинных тире (— и –): вместо них
запятая, точка или двоеточие.

Почему: решение владельца для Platina (2026-11-26) и правило Tenra («reads as AI-generated»).

Проверка: Platina `copy_lint.py` (CI) | аудит

Где: Tenra, Platina

Агенту: нет

## Коротко для агента

- Интерфейс приложений — только из DesignKit; чего нет — PR в DesignKit, в приложении тонкий
  переходник (DES-1). Только токены, без сырых значений (DES-2). Версию DesignKit поднимает его
  workflow, блок `designkit:agents` руками не правят (DES-3, DES-4).
- Сайты — на shadcn/ui, цвета только токенами темы (DES-7).
- Каждая строка интерфейса приложения — ключ каталога строк на всех языках проекта (DES-8).
