# Выпуск приложений

Как это устроено: приложение собирается в TestFlight workflow `testflight.yml` (ручной запуск на
`main`), владелец проверяет сборку на телефоне и отправляет её в App Store через App Store Connect.
Версию, заметки к выпуску и шаги в App Store Connect готовит сессия; нажимает «отправить» владелец.
DesignKit выпускается иначе: номер версии ставит его релиз-бот при мерже PR, а приложения
поднимают версию DesignKit своим workflow (`design.md`).

### REL-1. Сборка в TestFlight — из зелёного main

Правило: сборку для TestFlight запускают на `main`, когда его CI зелёный.

Почему: чеклист «Выпуск» стандарта; владелец ставит на телефон то, что уже прошло проверки.

Проверка: аудит

Где: приложения

Агенту: да

### REL-2. Версия поднята

Правило: перед выпуском в App Store поднимают версию приложения (`MARKETING_VERSION` или её
аналог в проекте).

Почему: чеклист «Выпуск» стандарта; App Store не примет сборку с версией, которая уже вышла.

Проверка: аудит

Где: приложения

Агенту: да

Правило: изменение, которое видит пользователь, записывают в заметки к выпуску проекта, на всех
языках, на которых приложение в магазине.

Почему: DoD стандарта (пункт 4) и чеклист «Выпуск».

Проверка: аудит

Где: приложения

Агенту: да

### REL-4. Шаги владельца — в строке состояния

Правило: когда для выпуска нужно действие владельца (App Store Connect, проверка на устройстве),
сессия перечисляет эти шаги и кончает сообщение `Статус: ждёт владельца — …`.

Почему: чеклист «Выпуск»; сервис Warehouse показывает строку владельцу как просьбу.

Проверка: аудит

Где: приложения

Агенту: да

### REL-5. Как выпускать — в docs/release.md проекта

Правило: подробности выпуска проекта (workflow, секреты, подводные камни, шаги владельца) записаны
в его `docs/release.md`.

Почему: чеклист «Выпуск» стандарта ссылается на этот файл.

Проверка: аудит

Где: приложения

Агенту: нет

### REL-6. Версию DesignKit ставит релиз-бот

Правило: PR в DesignKit добавляет заметку в `.changes/` и пишет `vNext` там, где нужна версия;
номер, `CHANGELOG.md`, тег и GitHub Release делает релиз-бот после мержа.

Почему: записано в `CLAUDE.md` DesignKit и `docs/releasing.md`.

Проверка: CI DesignKit `Changelog` | аудит

Где: DesignKit

Агенту: нет

## Коротко для агента

**Выпуск** (приложения). Версия поднята (REL-2). Заметки к выпуску на всех языках проекта
(REL-3). Сборка в TestFlight из зелёного `main` (REL-1). Шаги владельца перечислены в строке
состояния (REL-4). Подробности проекта — в его `docs/release.md`.
