# Метрики: дизайн

Подсистема 4 [дорожной карты](../roadmap.md). Владелец отдал решения сессии («Делай как
считаешь», 2026-11-28): всё ниже — решения сессии, владелец может поправить любое.

## Зачем

Деньги и реклама сейчас видны только в Tenra, и только раз в неделю. Субботняя сессия
вручную собирает цифры из RevenueCat, App Store Connect и Apple Ads в таблицу
`docs/promotion-plan.md` §6 Tenra. Строки часто остаются с «?»: в окружении сессии нет ключа
App Store Connect, а сама субботняя сессия иногда не проходит (21.11). При этом решения по
рекламе Tenra принимаются по этим цифрам: в §5 B её плана есть стоп-сигналы («пробный дороже
$15 — переносить бюджет»). Решение принималось по ручному снимку, сделанному раз в неделю.

Метрики в Warehouse отвечают владельцу на один вопрос: **как идут продукты и окупается ли
реклама, на сегодня, без сессии**. Каждое утро цифры уже собраны, а сигнал о дорогом пробном
приходит в «Ждёт вас» и в Telegram.

## Цели

- Сервис сам каждый день забирает цифры из трёх источников: RevenueCat, отчёты о продажах App
  Store Connect и Apple Ads. Сессия для этого не нужна.
- Страница `/metrics`: по каждому продукту установки, пробные, подписки, MRR, выручка, траты на
  рекламу, цена установки и пробного. За 7, 28 или 90 дней, с изменением к прошлому периоду и
  графиком по дням.
- Сигнал в «Ждёт вас» (заметка) и в утренней сводке Telegram: пробный за 7 дней дороже
  порога (по умолчанию $15, из стоп-сигнала Tenra; порог в настройках).
- Утренняя сводка Telegram получает строку на продукт за вчера: установки, пробные, траты.
- Источник, который не отвечает или не настроен, виден в настройках, как источники
  диспетчерской.

## Не цели

- Показы и просмотры страницы стора (отчёты аналитики App Store Connect живут по своему
  циклу «запроси отчёт — жди — скачай»): отдельная задача после первой версии.
- Оценки и отзывы: подсистема 6 «Обратная связь».
- Продуктовые метрики внутри приложений: события Tenra (`/v1/events`), North Star Dalada в
  Supabase, аналитика Google сайта Baja.kz. Это свои источники со своими ключами, следующие
  задачи.
- Управление рекламой: ставки, бюджеты, ключевые слова остаются в `ads.py` Tenra.
- Доступ сессий к метрикам (чтобы субботняя сессия Tenra брала цифры у Warehouse): отдельная
  задача, ей нужен свой способ входа.

## Чего нельзя (анти-цели)

- Ни одной цифры о деньгах в репозитории, в логах Actions и в ответах без входа владельца
  (репозиторий публичный, SEC-1, SEC-3). Метрики отдаёт только `/api/metrics` после проверки
  cookie, как `/api/board`.
- Ключи источников — только переменные окружения Vercel, в `.env.example` только их имена.
- Запросы к источникам не идут в каждом тике: раз в сутки на источник (плюс повтор после
  сбоя). У Apple и RevenueCat лимиты, а цифры за день всё равно меняются медленно.
- Цифры не пересчитываются из разных валют на глаз. Деньги RevenueCat — в его валюте отчёта
  (USD), траты Apple Ads — в валюте рекламного счёта; цена установки и пробного считается,
  только когда валюта трат и выручки одна или когда речь только о тратах (трата ÷ установки).

## Подходы

1. **Сервер Warehouse сам ходит в API источников (выбран).** Ключи в Vercel, сбор в тике раз в
   сутки, цифры в Postgres. Логи Vercel закрыты, поэтому деньги никуда не утекают, и не нужно
   шифрование, как у `seal.py` Tenra. Нужен шаг владельца: положить ключи в Vercel.
2. **Workflow в Tenra собирает цифры скриптами `asc.py` и `ads.py` и шлёт их в Warehouse.**
   Секреты уже лежат в репозитории Tenra. Но логи Actions публичные (любая ошибка печати
   выдаёт деньги), ключ RevenueCat там версии 1 (графиков у него нет), а Dalada и следующим
   продуктам понадобились бы свои копии. Отказ.
3. **Оставить сбор сессиям.** Так сейчас, и именно это не работает. Отказ.

## Как устроено

### Источники

| Источник | Что берём | Как | Ключи (Vercel) |
|---|---|---|---|
| RevenueCat API v2 | по дням: новые пробные, новые подписки (оплаты), активные подписки, MRR, выручка | графики проекта `GET /v2/projects/{id}/charts/{chart}` с дневным шагом; список проектов ключа `GET /v2/projects` | `REVENUECAT_API_KEYS` (секретные ключи v2, только чтение графиков; ключ v2 выдаётся на один проект RevenueCat, поэтому ключей может быть несколько, через запятую) |
| App Store Connect, отчёты о продажах | по дням и приложениям: новые загрузки, повторные загрузки | `GET /v1/salesReports` (SALES, SUMMARY, DAILY, версия 1_1), gzip TSV; строки по `Apple Identifier`, типы продукта: новая загрузка `1`, `1F`, `1T`, повторная `3`, `3F`, `3T` (как в `asc.py sales` Tenra) | `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8` (ключ с ролью Sales), `ASC_VENDOR_NUMBER` |
| Apple Ads Platform API | по дням и приложениям: показы, тапы, установки, траты | токен OAuth по client secret (JWT ES256), отчёт кампаний `POST /v1/reports/apps/campaigns/query` с дневным шагом, кампания → приложение по `adamId` (как `ads.py` Tenra) | `ADS_CLIENT_ID`, `ADS_TEAM_ID`, `ADS_KEY_ID`, `ADS_PRIVATE_KEY`, `ADS_ACCOUNT_ID` |

Пути и поля сверить с документацией и со скриптами Tenra (`appstore/asc.py`, `appstore/ads.py`)
при написании кода; тесты идут на сохранённых ответах (фикстурах), сеть в тестах не трогается.

### Чьи это цифры

- App Store Connect и Apple Ads отдают цифры по приложению (`Apple Identifier`, `adamId`).
  Приложение → проект по ссылке стора в паспорте (`links.store` в `docs/project.md`, его уже
  читает `syncDocs`; id — число после `id` в ссылке). Приложение без паспорта со ссылкой не
  отбрасывается: его строки хранятся под id приложения и показываются блоком «Без проекта».
- RevenueCat отдаёт цифры по своему проекту (у каждого ключа свой). Проект RevenueCat →
  проект Warehouse: по умолчанию проект Warehouse с тем же именем (RevenueCat «Tenra» →
  Tenra), в настройках можно выбрать другой.

### Хранение

Новая миграция `0006_metrics`:

- `metric_days (app text, source text, metric text, day date, value numeric, unit text,
  primary key (app, source, metric, day))`. `app` — id приложения App Store или
  `rc:<проект RevenueCat>`; проект ищется при чтении, а не при записи: поменялся паспорт —
  цифры переезжают сами. `unit` — `count` или код валюты.
- `metric_sources (source text primary key, synced_at timestamptz, ...)` или поля в
  существующей `sources`: когда источник последний раз собран и до какого дня есть данные.
  Здоровье источника — та же таблица `sources`, что у вебхуков и сверки (новые имена
  `revenuecat`, `appstore_sales`, `apple_ads`).
- Связь проектов RevenueCat с проектами Warehouse — в настройках (`settings`).

Выбор формы таблиц — за строителем; условие одно: повторный сбор тех же дней заменяет
значения, а не дублирует.

### Сбор

- В тике: для каждого настроенного источника, если с прошлого успешного сбора прошло больше
  суток (или прошлый не удался больше часа назад), собрать. Один источник — один шаг тика со
  своим тайм-аутом; сбой одного не мешает другим и тику.
- Первый сбор берёт 180 дней, чтобы у периода 90 дней был прошлый период для сравнения (отчёт о продажах — по дню на запрос, поэтому первый сбор растягивается на несколько тиков:
  не больше ~15 дней за тик). Каждый следующий —
  последние 7 дней заново: RevenueCat и Apple Ads досчитывают задним числом.
- Отчёт о продажах за вчера появляется у Apple к утру по Тихоокеанскому времени. Отсутствие
  отчёта за последний день — не сбой источника.
- Ответы источников в лог не печатаются (ни Vercel, ни `tick.yml`).

### Цифры и правила (`lib/domain/metrics.ts`, чистые функции)

За период (7, 28, 90 дней, кончая вчерашним днём; время UTC) и такой же период перед ним:

- Установки — новые загрузки App Store (повторные отдельно, мелко).
- Из рекламы — установки Apple Ads (по тапу и по показу, как в `ads.py` Tenra); цена
  установки = траты ÷ установки из рекламы.
- Пробные — новые пробные RevenueCat; установка → пробный = пробные ÷ установки.
- Цена пробного = траты ÷ пробные (только если у продукта есть и реклама, и RevenueCat).
- Оплаты — новые платные подписки RevenueCat (включая переходы из пробного).
- Активные подписки и MRR — значение на последний день периода, а не сумма.
- Выручка — сумма за период, **чистыми**: после комиссии Apple и налогов (так Tenra считает
  окупаемость: «$13 чистыми» с годовой). Хранится и до комиссии; если график RevenueCat
  чистых не отдаёт, показывается выручка до комиссии с подписью «до комиссии».
- Изменение к прошлому периоду — в процентах, со знаком; при нуле в прошлом периоде — «новое».
- Деление на ноль — «—», а не 0 или бесконечность. Мало данных (меньше 3 пробных за период) —
  цена пробного показывается, но без сигнала.

Сигнал «пробный дорогой»: цена пробного за последние 7 дней выше порога, при не меньше чем 3
пробных за эти дни. Заметка в «Ждёт вас» (уровень `note`, ключ `metrics:trial-cost:<проект>`),
уходит сама, когда цена опустилась. Порог — в настройках, по умолчанию 15 в валюте трат.

### Экран

Новый пункт «Метрики» в рамке `components/shell.tsx`, страница `app/(app)/metrics/` на
компонентах shadcn/ui и токенах темы. Данные — `GET /api/metrics?days=7|28|90` (только
владельцу; один ответ на всю страницу).

```
Метрики                                          [7 дней | 28 | 90]
Все продукты: 312 установок (+18%) · выручка $28 · реклама $236

┌ Tenra ───────────────────────────────────────────────────────────┐
│ Установки 138 ↑12%   Пробные 3 ↓40%   Оплаты 0   Подписки 1       │
│ MRR $0   Выручка $0   Реклама $62 ↓5%                             │
│ Установка $0,59 · Пробный $20,7 (порог $15) · Установка→пробный 2,2% │
│ [график по дням: установки и пробные столбиками, траты линией]    │
└──────────────────────────────────────────────────────────────────┘
┌ Dalada ──────────────────────────────────────────────────────────┐
│ Установки 41 ↑3%   (RevenueCat и реклама не подключены)           │
└──────────────────────────────────────────────────────────────────┘
Источники: RevenueCat сегодня 06:10 · Продажи App Store до 27.11 · Apple Ads сегодня 06:12
```

- Продукты — те проекты, у которых есть хотя бы одна цифра; порядок — по установкам за период.
- Карточка показывает только метрики подключённых к продукту источников; про остальные одна
  строка «не подключены».
- Если ключи не заданы ни для одного источника — пустое состояние с тем, какие переменные
  положить в Vercel (ссылка на `docs/setup.md`).
- Числа: целые с пробелом тысяч, деньги с валютой, проценты до целого (до десятой ниже 10%).
  Оценок времени здесь нет.

### Утренняя сводка

Сводка уходит каждое утро, когда есть цифры за вчера, даже если в «Ждёт вас» пусто: это
одно сообщение в день, и ради него метрики и делаются. В настройках его можно выключить
(«Цифры в утренней сводке»). Строка на продукт с цифрами за вчера: «Tenra: 21 установка, 1 пробный, реклама
$9». Продажи App Store за вчера к утренней сводке (03:00 UTC) обычно ещё нет: тогда строка
говорит про позавчера и называет день. Сигнал о дорогом пробном идёт обычной заметкой.

### Настройки

Раздел «Метрики» на `/settings`: состояние каждого источника (настроен ли ключ, когда собран,
последняя ошибка), связь проектов RevenueCat с проектами, порог цены пробного, цифры в утренней сводке.

## Что нужно от владельца

Положить ключи в Vercel (имена — в таблице источников) (Production) и передеплоить. Ключи App Store Connect и Apple Ads можно
взять те же, что в секретах Tenra (если файлы ключей сохранились), или выпустить новые; ключ
RevenueCat нужен новый, версии 2, только на чтение графиков. Шаги — в `docs/setup.md`, раздел
«Метрики». Без ключей код работает и показывает, каких ключей не хватает.

## Решения сессии после проверки строителем

Строитель задал три вопроса; владелец решения отдал сессии, поэтому решены так:
- Утренняя сводка уходит каждое утро ради цифр, с выключателем в настройках.
- Ключей RevenueCat может быть несколько (ключ v2 — на один проект).
- Выручка — чистыми, с запасным вариантом «до комиссии».

## Оставлено строителю

- Форма таблиц и типы чисел в базе (условие — замена при повторном сборе).
- Точные имена графиков RevenueCat и его параметры — по его документации на момент написания.
- Разбиение кода по файлам, клиенты API, формат фикстур.
- Вид графика (компонент chart shadcn/ui), подписи осей, подсказки.
