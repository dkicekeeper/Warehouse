# Метрики: план

> **Для исполнителя:** задачи по порядку, флажки `- [ ]`; навык superpowers:executing-plans.

**Цель:** сервис сам раз в сутки собирает цифры RevenueCat, продаж App Store и Apple Ads,
показывает их на `/metrics`, шлёт сигнал о дорогом пробном и строку цифр в утренней сводке.

**Устройство:** три клиента источников (`lib/metrics/`) отдают дни как `MetricDay`; сборщик в
тике пишет их в `metric_days`; чистые функции `lib/domain/metrics.ts` считают периоды, сигналы и
строки сводки; `/api/metrics` и страница читают одно и то же.

**Стек:** Next.js 16, TypeScript, Postgres (PGlite в тестах), shadcn/ui (`components/ui/chart.tsx`
уже есть), `node:crypto` для JWT ES256, `node:zlib` для gzip отчёта о продажах.

**Дизайн:** [2026-11-28-metrics-design.md](2026-11-28-metrics-design.md) — читать вместе с планом.

## Общие условия

- Цифры о деньгах только за cookie владельца (`/api/metrics`); ни в логах, ни в ответе тика
  (`tick.yml` печатать ответ нельзя), ни в тексте ошибок источников (в `sources.note` — код
  ответа и путь, без тела).
- Ключи — переменные окружения; в `.env.example` только имена: `REVENUECAT_API_KEYS`,
  `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`, `ASC_VENDOR_NUMBER`, `ADS_CLIENT_ID`,
  `ADS_TEAM_ID`, `ADS_KEY_ID`, `ADS_PRIVATE_KEY`, `ADS_ACCOUNT_ID`.
- Источник собирается раз в сутки после успеха, повтор после сбоя через час; первый сбор 180
  дней, следующие — последние 7 дней заново; отчёт о продажах не больше 15 дней за тик.
- Тексты интерфейса на русском, деньги с валютой, деление на ноль — «—».
- Тесты на сохранённых ответах в `tests/fixtures/metrics/`; сеть не трогается. Вышедшую миграцию
  не правят.
- Каждая задача: сначала падающий тест, потом код; `pnpm test`, `pnpm typecheck`, `pnpm lint`
  зелёные перед коммитом.

## На что смотреть при ревью

1. День без данных у одного источника (Apple ещё не выложил продажи за вчера): период не
   «проседает» тихо — в ответе у источника видно «данные до <день>».
2. Повторный сбор тех же дней (каждый день 7 дней заново) заменяет значения, а не складывает.
3. Приложение App Store без паспорта со ссылкой стора: его цифры видны блоком «Без проекта», не
   пропадают.
4. Траты в одной валюте, выручка в другой: цена пробного считается (траты ÷ пробные), сравнение
   «реклама окупается» по валютам не делается.
5. Источник упал посреди сбора 180 дней: уже собранные дни сохранены, следующий тик продолжает с
   места, а не с начала.

### Task 1: модель и расчёты (`lib/domain/metrics.ts`)

**Файлы:** создать `lib/domain/metrics.ts`, `tests/domain/metrics.test.ts`.

**Интерфейсы (производит):**

```ts
export type MetricSource = 'revenuecat' | 'appstore_sales' | 'apple_ads';
export type MetricName =
  | 'installs' | 'redownloads'                       // appstore_sales
  | 'ad_impressions' | 'ad_taps' | 'ad_installs' | 'ad_spend'   // apple_ads
  | 'trials_new' | 'paid_new' | 'actives' | 'mrr' | 'revenue_net' | 'revenue_gross'; // revenuecat
export interface MetricDay { app: string; source: MetricSource; metric: MetricName; day: string /* YYYY-MM-DD */; value: number; unit: string /* 'count' | ISO currency */ }
export interface Money { amount: number; currency: string }
export interface KPI { value: number | Money | null; previous: number | Money | null; change: number | null /* доля, 0.12 = +12% */ | 'new' }
export interface ProductMetrics {
  projectId: string | null; name: string; sources: MetricSource[];
  installs: KPI; redownloads: KPI; adInstalls: KPI; trials: KPI; paid: KPI;
  actives: KPI; mrr: KPI; revenue: KPI & { net: boolean }; adSpend: KPI;
  costPerInstall: Money | null; costPerTrial: Money | null; installToTrial: number | null;
  daily: { day: string; installs: number; trials: number; adSpend: number }[];
  dataUntil: Partial<Record<MetricSource, string>>;
}
export function appOwner(projects: { id: string; name: string; storeUrl: string | null }[], rcProjects: Settings['revenuecatProjects']): (app: string) => { projectId: string | null; name: string };
export function summarize(rows: MetricDay[], owner: (app: string) => { projectId: string | null; name: string }, days: 7 | 28 | 90, today: Date): ProductMetrics[];
export function trialCostAlerts(products: ProductMetrics[] /* days = 7 */, limit: number): { projectId: string | null; name: string; cost: Money }[];
export function digestLines(rows: MetricDay[], owner: (app: string) => { projectId: string | null; name: string }, today: Date): string[];
```

`app` — id приложения App Store (строка цифр) или `rc:<id проекта RevenueCat>`. `storeUrl` → id:
число после `/id` в ссылке. `rc:` приложение относится к проекту, выбранному в
`rcProjects[id].projectId`, а без выбора — к проекту с тем же именем, что `rcProjects[id].name`
(без учёта регистра). Тип `Settings['revenuecatProjects']` вводит задача 2; в задаче 1 его
можно объявить здесь и потом перенести.

- [ ] **Шаг 1: падающие тесты** (`tests/domain/metrics.test.ts`), значения из дизайна:
  - `summarize` за 7 дней: период кончается вчера (UTC), прошлый период — 7 дней перед ним;
    `installs` = сумма `installs`, `actives` и `mrr` — значение последнего дня, `revenue` —
    сумма `revenue_net` (`net: true`); без `revenue_net` — сумма `revenue_gross`, `net: false`.
  - `change`: 110 к 100 → `0.1`; к 0 → `'new'`; 0 к 0 → `null`.
  - `costPerInstall` = `ad_spend` ÷ `ad_installs`; 0 установок → `null`.
  - `costPerTrial` = траты ÷ пробные, только при обоих источниках; `installToTrial` = пробные ÷
    установки.
  - Два продукта сортируются по установкам за период; приложение без проекта — `name: 'Без проекта'`.
  - `dataUntil` — последний день с данными у каждого источника продукта.
  - Строки, пришедшие дважды за один день (повторный сбор), в `summarize` не попадают: это
    обязанность хранилища, тест на это — в задаче 2.
  - `trialCostAlerts`: 3 пробных и траты $62 (цена $20,7) при пороге 15 → сигнал; 2 пробных —
    нет; $40 при 3 пробных — нет.
  - `digestLines`: «Tenra: 21 установка, 1 пробный, реклама $9» за вчера; продажи за вчера нет →
    строка за позавчера с днём: «Tenra, 26 нояб.: 18 установок…»; продукт без цифр — без строки.
    Числительные через `plural` из `components/format.ts` (перенести в `lib/domain`, если
    компоненту и домену нужен один).

### Task 3: клиент App Store Connect (продажи)

**Файлы:** создать `lib/metrics/jwt.ts`, `lib/metrics/appstore.ts`,
`tests/metrics/appstore.test.ts`, фикстура `tests/fixtures/metrics/sales-2026-11-20.tsv`
(придуманные строки в формате отчёта SALES SUMMARY 1_1: заголовок и строки с `Apple Identifier`,
`Product Type Identifier`, `Units`).

**Интерфейсы (производит):**

```ts
// jwt.ts
export function es256Jwt(header: Record<string, unknown>, claims: Record<string, unknown>, pemOrBareKey: string): string;
// appstore.ts
export interface AppStoreConfig { keyId: string; issuerId: string; privateKey: string; vendorNumber: string }
export function appStoreConfig(env: NodeJS.ProcessEnv): AppStoreConfig | null;
export function parseSalesReport(tsv: string, day: string): MetricDay[];
export async function fetchSalesDay(cfg: AppStoreConfig, day: string, fetchFn?: typeof fetch): Promise<MetricDay[] | 'not_yet'>;
```

- JWT: `crypto.sign('sha256', data, { key, dsaEncoding: 'ieee-p1363' })` (подпись r‖s, не DER);
  `aud: 'appstoreconnect-v1'`, срок 20 минут; ключ принимается и PEM, и голым base64 (как
  `private_key()` в `asc.py` Tenra).
- Запрос: `GET https://api.appstoreconnect.apple.com/v1/salesReports` с
  `filter[frequency]=DAILY`, `filter[reportType]=SALES`, `filter[reportSubType]=SUMMARY`,
  `filter[vendorNumber]`, `filter[reportDate]=<день>`, `filter[version]=1_1`, `Accept:
  application/a-gzip`; ответ gunzip → TSV. 404 с кодом отчёта «нет данных за день» → `'not_yet'`.
- Разбор: `installs` = сумма `Units` строк с типом `1`, `1F`, `1T`; `redownloads` — `3`, `3F`,
  `3T`; по `Apple Identifier`; возвраты (отрицательные Units) вычитаются.

- [ ] **Шаг 1: падающие тесты:** `parseSalesReport` на фикстуре: два приложения, новые и
  повторные загрузки, строка покупки внутри приложения (тип `IA1`) не считается; `es256Jwt`
  проверяется `crypto.verify` с `dsaEncoding: 'ieee-p1363'` на ключе, созданном в тесте
  (`generateKeyPairSync('ec', { namedCurve: 'P-256' })`); `fetchSalesDay` с поддельным
  `fetchFn`: правильный URL и заголовки, gzip-ответ разобран, 404 → `'not_yet'`, 401 →
  исключение с кодом, без тела ответа.
- [ ] **Шаг 2:** падают. **Шаг 3:** реализовать. **Шаг 4:** зелёные. **Шаг 5:** коммит.
