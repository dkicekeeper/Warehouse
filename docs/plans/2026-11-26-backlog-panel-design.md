# Панель бэклога: дизайн

Подсистема 3 [дорожной карты](../roadmap.md). Одобрен владельцем 2026-11-26 («На сайте ничего не
изменилось, я хочу это видеть на дашбордах»).

## Зачем

Все шесть репозиториев ведут задачи, планы и решения файлами по одному стандарту, но увидеть их
можно только в GitHub, по одному репозиторию. Владелец хочет открыть Warehouse и видеть по всем
проектам: что открыто, что ждёт его, какие планы в работе, что решено, на какой стадии проект.

## Цели

1. Сервис сам читает `docs/project.md`, `docs/backlog/`, `docs/plans/`, `docs/decisions/` из основной
   ветки каждого репозитория; после мержа изменение видно на странице в пределах минуты-двух.
2. На главной: отдельный блок «Задачи ждут вас» (задачи с `needs-owner` из всех проектов) и у
   каждого проекта стадия и число задач со ссылкой на них.
3. Страница `/backlog`: все задачи с фильтром по проекту и состоянию; у выбранного проекта паспорт,
   планы в работе и решения. У каждой записи ссылка на файл в GitHub.

## Не цели

- Менять задачи с сайта: правят сессии и владелец в GitHub.
- Сообщения в Telegram о задачах.
- Архив (сделанные задачи, выполненные планы) и бессрочные документы.
- Замок на задачу и «кто взял»: это подсистема 5.

## Чего нельзя допустить

- Данные проектов без входа владельца: `/api/backlog` проверяет cookie, как `/api/board`.
- Половина репозитория на странице: записи репозитория заменяются одним запросом.
- Расход лимита GitHub на репозитории, где ничего не менялось.

## Подходы

1. **Сервис читает GitHub сам (выбрано).** Приложение GitHub уже имеет чтение содержимого и получает
   событие о пуше. Новых секретов и workflow не нужно; приватный Baja.kz читается так же.
2. Workflow `standard.yml` каждого проекта отправляет `lint.py --json` в сервис. Потребовался бы
   секрет в шести репозиториях, а в публичных логах появился бы адрес приёмника.
3. Читать GitHub при каждом открытии страницы. Медленно и расходует лимит.

Блок на главной (выбор владельца 2026-11-26): задачи «ждёт владельца» идут **отдельным блоком**, а
не в общем «Ждёт вас»: просьбы сессий срочные и исчезают сами, задачи висят неделями.

## Как устроено

- **Разбор.** `lib/domain/docs.ts` читает шапку тем же способом, что `standard/lint.py`; тест
  сравнивает оба на одних файлах. Файл без шапки остаётся записью без статуса.
- **Хранение.** Миграция `0004_project_docs`: таблица `project_docs` (репозиторий, путь, вид, поля,
  текст до 2000 символов, sha файла) и у `repos` отметка «прочитать» и sha прочитанного дерева `docs`.
- **Сбор.** `GithubApp.syncDocs`: дерево основной ветки (один запрос), если sha папки `docs` не
  изменился — всё; иначе дерево `docs` и по запросу на каждый изменившийся файл. Пуш в основную
  ветку ставит репозиторию отметку «прочитать»; тик читает отмеченные каждый раз и все раз в
  30 минут (это же чинит потерянный вебхук). Источник `docs_sync` хранит время и ошибку.
- **Вид.** `lib/domain/backlog.ts` собирает записи по проектам, считает задачи и отбирает те, что
  ждут владельца. `/api/board` добавляет к ответу сводку `backlog`, `/api/backlog` отдаёт всё.
- **Страницы.** Главная: блок и счётчики. `/backlog`: клиентская страница, проект хранится в адресе
  (`?project=`).

## Проверка

Тесты разбора, хранилища (PGlite и настоящий Postgres в CI), сбора с подставным GitHub, тика,
вида, API (отказ без входа) и браузерные тесты страниц на телефоне и столе. На боевом сервисе: после
мержа в `/backlog` видны задачи всех шести репозиториев, а правка задачи в GitHub доходит до
страницы.
